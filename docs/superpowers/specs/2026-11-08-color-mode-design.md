# 配色の流儀を選べるようにする (設計)

日付: 2026-11-08
状態: 実装済み (Issue #67)

## 1. 背景と狙い

色の相性 (`evaluatePalette`, 総合点の 45%) は色相環の一般理論と「ベーシックカラー」の概念で決めている。
アズーロ・エ・マローネ (紺 × 茶) のような定番配色は特別扱いされず、ネイビー × ブラウン (ベーシック同士 0.85) が
紺 × 真っ赤 (ベーシック + 差し色 0.92) より低く出る。利用者が自分の好みの「流儀」を選べると、提案の説得力が上がる。

design-critique スキルで案をレビューした結果 (Issue #67 に記録) を前提にする。要点は 3 つ。

1. モードは if 分岐ではなく **データ定義** にし、理由文にモードの語彙を出す。
2. 実データで **上位 5 件に差が出る** ことを出荷条件にする。
3. 置き場所は **条件欄の外**。好みとして記憶し、既定は現行ロジックのまま。

## 2. ゴール / 非ゴール

**ゴール**

- 「標準」「イタリア流」「イギリス流」から色合わせの基準を選べる。選択はリロード後も保持される。
- 既定 (標準) では現行の提案結果・理由文が 1 件も変わらない。
- 提案カードの理由文に「アズーロ・エ・マローネ」のようなモード固有の配色名が出る。
- 375×740 で提案の先頭位置が今より下がらない。

**非ゴール**

- 厚さ・テイスト・季節・鮮度の採点は変えない。
- フレンチなど 4 つ目以降のモード (データ定義にしておき、後から足せる形にはする)。
- 服ごとの「この色はこう扱う」といった個別設定。

## 3. ロジック

### 3.1 モードの定義 (`src/lib/colorMode.ts`)

```ts
type ColorMode = 'standard' | 'italian' | 'british';
interface ColorModeDef {
  label: string;        // 利用者向けの名前
  description: string;  // 1 行説明 (title と選択行に出す)
  pairs: PairRule[];    // 色ファミリー同士の加点表
  toneOnToneBonus: number;        // 「ワントーン」「類似色でまとめた配色」への加点
  vividAccentPenalty: number;     // 彩度 0.65 超の差し色があるときの減点
  avoid: PairRule[];              // 減点するペア (理由は warning に出す)
  formality?: FormalityRule;      // テイストと連動する加点・減点
}
```

色ファミリーは `colorFamily` の 14 種に、**ボルドー** (red で明度 0.35 以下) を加えた「トーン」で照合する。
真っ赤とボルドーを区別しないと「ネイビー × ボルドー」の加点が紺 × 真っ赤にも効いてしまうため。

| モード | 加点ペア (名前) | 減点 | テイスト連動 |
| --- | --- | --- | --- |
| 標準 | なし。現行の `evaluatePalette` の結果をそのまま返す | なし | なし |
| イタリア流 | ネイビー/ブルー × ブラウン +0.08「アズーロ・エ・マローネ」、グレー × ブラウン +0.07、ネイビー × ボルドー +0.08、ベージュ × ネイビー +0.06、カーキ × ブラウン +0.06、ワントーン/類似色 +0.05「トーン・オン・トーン」 | 鮮やかな差し色 −0.08 | なし |
| イギリス流 | ネイビー × グレー +0.08「英国調のネイビー × グレー」、ネイビー × ホワイト +0.06、グレー × ボルドー +0.07、ネイビー × ボルドー +0.05、ブラック × グレー +0.04 | ネイビー × ブラック −0.12「紺と黒は合わせない」 | smart/formal で茶・カーキがあれば −0.10「街着では茶より黒・グレー」。casual で茶・カーキ・グリーン・イエロー・オレンジがあれば +0.06「カントリー調のアースカラー」 |

加点は **最も大きい 1 件** を採用し、2 件目以降は +0.02 ずつ、合計 0.10 まで。最終値は 0〜1 に収める。
(実装時の調整: 当初の +0.10 / +0.03 / 上限なしでは、実データの冬の上位 5 件がすべて 100 点に張り付いた。)
採用したペアの名前を `scheme` (理由文の先頭) にする。減点は `warning` として提案カードの ⚠ 行に出す。

### 3.2 採点への組み込み (`src/lib/outfit.ts`)

- `SuggestOptions.colorMode?: ColorMode` を追加。未指定は `'standard'`。
- `scoreOutfit` は `evaluatePalette` の結果を `applyColorMode(base, hexes, mode, { formality })` に通す。
  `formality` は条件の「テイスト」指定があればそれ、無ければコーデの多数派 (`dominantFormality`)。
- `breakdown.color` と `scheme` はモード適用後の値。

### 3.3 記憶

`localStorage` キー `coordination.colorMode.v1` に文字列でモード id を保存。読めない・不正な値は `'standard'`。

## 4. 画面

条件欄の状態行 (`cond-status`: 地点 / 予報 / 気温を変える / ピル) に **「色合わせ: 標準 ▾」** のリンクを足す。
押すと下に 1 行開き、既存の `Segmented` で「標準 / イタリア流 / イギリス流」を選び、右に 1 行説明が出る。
「地点を変える」「気温を変える」と同じ開閉パターンなので、閉じている間の高さは変わらない。

- セグメントの各ボタンには `title` で 1 行説明を付ける。
- 「現在のロジック」「選定モード」という語は使わない。利用者向けは「色合わせの基準」。
- 国旗や絵文字だけのラベルにしない。

## 5. 受け入れ条件 (Issue #67 と同じ)

1. 既定 (標準) で既存テストが無修正で通る。
2. 実データ (51 点) で 3 モードの上位 5 件を比べ、モード間で少なくとも 2 件が入れ替わる。
3. 理由文にモード固有の配色名が出る (単体テスト)。
4. イギリス流で formality=smart のとき、茶靴入りのコーデが標準より下がる (単体テスト)。
5. 375×740 で提案の先頭位置が今より下がらない (Playwright)。
6. 選択がリロード後も保持される。

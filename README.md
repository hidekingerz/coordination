# Coordination

手持ちの服のデータをもとに、**日付（季節）・気温・色味** を考慮したコーディネートを提案する Web アプリです。
サーバー不要で、データはブラウザの localStorage に保存されます。

## できること

- **クローゼット管理**: 服をカテゴリ・色（主色 / 副色）・着る季節・厚さ・テイスト・タグ付きで登録、編集、削除
- **コーデ提案**: 日付（省略時は今日）と任意の気温・テイスト・「このアイテムを着たい」指定から、上位 5 コーデを提案
- **提案の根拠を表示**: 配色の種類（モノトーン / ベーシック＋差し色 / 類似色 など）、厚さの適合、テイストの統一、季節外れの警告
- **着用履歴**: 「このコーデを着た」「今日着た」で記録。最近着た服は提案で控えめにし、長く着ていない服を優先するモードも。クローゼットは「着ていない順」に並べ替え可能
- **JSON のエクスポート / インポート**: バックアップや別ブラウザへの移行に（着用履歴も含む）
- **Gist からの取り込み**: GitHub Gist に貼った JSON を URL（または ID）から直接読み込み。手書きしやすいよう日本語ラベルや色名も受け付けます
- **サンプルデータ**: 空の状態からすぐに試せる 30 点のサンプルクローゼット

## 使い方

```bash
npm install

```


## Gist / JSON からクローゼットを取り込む

クローゼット画面の「インポート」から、次のいずれかで取り込めます。

- GitHub Gist のページ URL（`https://gist.github.com/you/<id>`）、Gist の ID、または「Raw」ボタンの URL
- GitHub リポジトリ上のファイルの URL（`.../blob/...` は自動で raw に変換）
- JSON を直接貼り付け、またはファイルを選択

Secret gist も URL があれば読み込めます。Gist 内に複数ファイルがあるときは `.json` を優先し、読めるものを自動で選びます。
取り込み前に件数と内容のプレビューが出て、「既存に追加（同じ ID は上書き）」か「置き換え」を選べます。最後に使った URL は記憶されるので、Gist を編集したあとは「読み込む」を押すだけで更新できます。

### データ形式

アプリのエクスポートと同じ `{ "items": [...] }` のほか、配列をそのまま置いても構いません。手書きする場合は最低限 `name` と `category` があれば取り込めます。

```json
[
  { "name": "白のTシャツ", "category": "トップス", "color": "白", "seasons": "春,夏", "warmth": 1, "formality": "カジュアル", "tags": "Tシャツ" },
  { "name": "ネイビーのステンカラーコート", "brand": "無印良品", "category": "outer", "color": "#1f2a44", "seasons": ["autumn", "winter"], "warmth": 4, "formality": "smart" },
  { "name": "白のレザースニーカー", "category": "靴", "color": "white", "seasons": "通年" }
]
```

| 項目 | 必須 | 受け付ける値 |
| --- | --- | --- |
| `name` | ○ | 名前 |
| `category` | ○ | `outer` / `tops` / `bottoms` / `onepiece` / `shoes` / `accessory`、または「アウター」「トップス」「パンツ」「靴」「小物」などの日本語 |
| `color` | | `#rrggbb`、または「白」「ネイビー」「ベージュ」「カーキ」「ボルドー」「navy」などの色名。無ければグレー |
| `subColor` | | 副色。`color` と同じ形式 |
| `seasons` | | 配列または「春,夏」のような文字列。「通年」「秋冬」も可。無ければ通年 |
| `warmth` | | 1（真夏）〜 5（真冬）。無ければ 3 |
| `formality` | | `casual` / `smart` / `formal`、または「カジュアル」「きれいめ」「フォーマル」。無ければカジュアル |
| `brand`, `tags`, `imageUrl` | | 任意。`tags` は配列かカンマ区切り |
| `id` | | 省略すると名前・カテゴリ・ブランドから安定した ID を作るので、同じ Gist を再取り込みしても重複しません |

補完した項目はプレビューに警告として表示されます。

## 商品情報から服データを作る (Claude Code スキル)

`.claude/skills/wardrobe-from-products/` に、ブランドの商品情報からこのアプリ用の JSON を作る Claude Code 用スキルが入っています。
このリポジトリで Claude Code を使い、「ユニクロの https://www.uniqlo.com/jp/ja/products/E486119-000/00 を買った。アプリ用のデータにして」
「今月買った服を Gist 用の JSON にして（無印のオックスシャツ 白、GU のタックワイドパンツ ベージュ…）」のように頼むと、

- ユニクロ / GU は商品 API から商品名・素材・カテゴリ・色ごとの画像を自動取得
- 他ブランドは商品ページの取得を試み、取れなければ商品名・色・素材の貼り付けを依頼
- 素材や種類から厚さ・季節・テイストを判定し、色をアプリと相性のよい hex に変換
- 作った JSON をアプリと同じ解析ロジックで検証して一覧表示

という流れで `wardrobe-import.json`（.gitignore 済み）を作ります。できた JSON を Gist に貼ってアプリの「インポート」から読み込んでください。

## 提案ロジックの概要

スコアは 4 つの観点の加重和です（`src/lib/outfit.ts`）。

| 観点 | 重み | 内容 |
| --- | --- | --- |
| 色 | 45% | 全アイテムの色をペアごとに評価。ベーシックカラー（白・黒・グレー・ネイビー・ベージュ・ブラウン・カーキ）はどの色とも相性が良いとみなし、有彩色同士は色相差で「同系色 / 類似色 / 補色 / 相性が悪い」を判定。差し色が 3 系統以上あると減点 |
| 厚さ | 30% | 気温（または季節と月内の進行）から目標の厚さ 1〜5 を決め、コーデ全体の体感的な厚さ（アウターを重視）との差で評価。寒い日にアウターが無いと減点 |
| テイスト | 15% | カジュアル / きれいめ / フォーマルの統一度。指定があればそれへの近さも考慮 |
| 季節 | 10% | 各アイテムの着用季節が今日の季節に合っているか。季節の境目（最初と最後の約 3 週間）は隣の季節の服も許容 |
| 鮮度 | 0 / 10% / 30% | 着用履歴から。最後に着てから 2 週間で 1.0 に戻る鮮度（未着用は 1.0）をコーデ全体で平均し、上の 4 観点の合計と加重和にする。同じ組み合わせを 1 週間以内に着ていれば半減。画面の「着用履歴」で 考慮しない / 標準 / 着ていない服を優先 を切り替え |

季節は日本の一般的な区分（3〜5 月 春、6〜8 月 夏、9〜11 月 秋、12〜2 月 冬）です。
着用履歴は服データとは別に localStorage に保存し（`src/lib/wear.ts`）、「未着用」を提案理由に挙げるのはクローゼットの半数以上に記録がたまってからにしています。
色の判定ロジックは `src/lib/color.ts`、季節と気温の変換は `src/lib/season.ts` にあります。

## 構成

```
src/
  App.tsx                 タブ切替と永続化
  types.ts                データ型と表示ラベル
  lib/color.ts            色の解析・分類・相性スコア
  lib/season.ts           日付 → 季節、気温 → 目標の厚さ
  lib/outfit.ts           コーデ生成とスコアリング
  lib/storage.ts          localStorage と JSON 入出力 (手書き JSON の補完も)
  lib/wear.ts             着用履歴と鮮度の計算
  lib/gist.ts             Gist / URL からの取得
  data/sample.ts          サンプルクローゼット
  components/             画面コンポーネント
```

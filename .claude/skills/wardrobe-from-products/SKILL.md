# 商品情報からクローゼット用データを作る

このリポジトリのアプリ (Coordination) は、服を **カテゴリ・色・季節・厚さ・テイスト** で持っていて、
それをもとにコーデを提案する。提案の質はこの 5 項目の精度で決まるので、このスキルの仕事は
「商品ページの売り文句」を「アプリが判断に使える属性」に正しく翻訳すること。

出来上がった JSON はユーザーが Gist に貼ってアプリの「インポート」から読み込む
(`src/lib/storage.ts` の寛容な解析が通る形なら何でもよいが、ここでは正規形で出す)。

## 出力形式

配列で出す。1 商品 1 要素。ユーザーが同じ商品を色違いで持っていれば色ごとに 1 要素。

```json
[
  {
    "id": "uniqlo-486119-04",
    "name": "スウェットフルジップパーカ (グレー)",
    "brand": "ユニクロ",
    "category": "tops",
    "color": "#8a8a8a",
    "subColor": null,
    "seasons": ["spring", "autumn", "winter"],
    "warmth": 3,
    "formality": "casual",
    "tags": ["スウェット", "パーカ", "綿100%"],
    "imageUrl": "https://image.uniqlo.com/.../jpgoods_04_486119_3x4.jpg"
  }
]
```

各項目の取りうる値と意味は `references/output-format.md` を見る (短いので最初に一度読む)。
特に `warmth` (1=真夏 … 5=真冬) と `seasons` は提案のフィルタに直結するので丁寧に決める。

`id` は `ブランド英字-商品番号-色コード` のように **再実行しても同じ値になる形** にする。
アプリは同じ id を上書きするので、あとで属性を直して再取り込みしても重複しない。
商品番号が無いときは id を省略してよい (アプリが名前とブランドから安定した id を作る)。

## 進め方

### 1. 入力を仕分ける

| 入力 | やること |
| --- | --- |
| ユニクロ / GU の URL・商品番号・商品名 | `scripts/fetch-fr-product.mjs` で API から取得 (下記) |
| それ以外のブランドの URL | `WebFetch` を 1 回だけ試す。多くのブランド EC はボット対策で 403/503 になるので、失敗したら粘らず、ユーザーに商品名・色・素材・カテゴリの貼り付けを頼む (頼み方は `references/brands.md`) |
| 貼り付けられた商品説明・購入メール・買い物メモ | そのテキストから属性を読み取る。足りない項目は下の判定ルールで推定し、推定したことを伝える |
| 「ユニクロのスウェットパーカ グレー」のような一文 | 商品名で API 検索 (`--limit 3`) し、候補が複数ならどれか確認する |

### 2. ユニクロ / GU は API で取る

```bash
node .claude/skills/wardrobe-from-products/scripts/fetch-fr-product.mjs <URL | E486119-000 | 検索語> [--brand gu] [--limit 3]
```

商品名・価格・性別・カテゴリ階層 (`category.class/category/subcategory`)・素材 (`composition`)・
フィット感 (`designDetail`)・色一覧 (`colors[].code/name/hex/chipImage/image/productUrl`) が JSON で返る。

- **色はユーザーが買った色だけ** を出す。URL に `colorDisplayCode=04` や末尾 `/00?colorDisplayCode=` があればそれ。
  指定が無く色が複数あるなら、色一覧 (コードと色名) を見せて「どの色を持っていますか」と聞く。これだけはユーザーにしか分からない。
- `colors[].hex` は色名からの推定値。WINE と RED、OLIVE と DARK GREEN のように名前だけでは曖昧な色は
  `chipImage` をダウンロードして Read で見て、実物に近い hex に直す (色がコーデ提案の 45% を占めるので、ここは手を抜かない)。
- `imageUrl` には買った色の `image` を入れる。
- 商品番号 `E486119-000` から id を `uniqlo-486119-04` (GU なら `gu-`) の形にする。

### 3. 属性を決める (全ブランド共通)

判断の根拠と対応表は `references/mapping.md` にある。迷ったらそちらを読む。要点:

- **category**: 商品のカテゴリ階層やアイテム名から。パーカ・ニット・シャツ→ `tops`、コート・ブルゾン・ダウン・カーディガン(羽織り)→ `outer`、
  パンツ・スカート→ `bottoms`、ワンピース・セットアップ→ `onepiece`、靴→ `shoes`、バッグ・帽子・マフラー・ベルト→ `accessory`。
- **color**: `#rrggbb`。ブランドの色名は見栄え優先 (「ナチュラル」「スモーキーブルー」) なので、色名→hex の表と商品画像で確かめる。
  柄物やバイカラーは `subColor` に 2 色目。アプリは白・黒・グレー・ネイビー・ベージュ・ブラウン・カーキを「どの色とも合うベーシック」として扱うので、
  それらに該当する色は迷わずその代表値に寄せる方が提案が安定する。
- **warmth** (1〜5): 素材と機能名で決める。綿 T シャツ・リネン=1、薄手長袖・オックスシャツ=2、スウェット・デニム・チノ=3、
  ウール・フリース・中厚ニット=4、ダウン・ヒートテック極暖・ウールコート=5。アウターはそれ単体の厚さ。
- **seasons**: warmth から素直に。1→夏 (+春・秋の暑い時期なら春夏秋)、2→春夏秋、3→春秋 (+冬のインナー用途なら冬も)、4→秋冬、5→冬。
  通年で履くデニム・スニーカーは 4 季節。
- **formality**: アイテムの種類で決める。スウェット・パーカ・T シャツ・スニーカー・ショーツ=`casual`、
  シャツ・スラックス・ニット・ローファー・チェスターコート=`smart`、スーツ・セットアップ・ドレスシューズ=`formal`。
  同じカテゴリでも「感動パンツ」「スマートアンクルパンツ」のように名前がきれいめを示していれば `smart`。
- **tags**: 検索に効く語を 2〜5 個。アイテム種別、主素材、機能名 (ヒートテック・エアリズム等)、シルエット。
- **name**: 「商品名 (色)」。ブランド名は `brand` に入れるので name には含めない。

推定で埋めた項目はユーザーに一言伝える (「素材不明だったので warmth=3 にしました」)。黙って埋めない。

### 4. 検証する

```bash
npx tsx .claude/skills/wardrobe-from-products/scripts/validate.ts <作成した.json>
```

アプリと同じ解析を通し、1 件ずつ「カテゴリ / 色 / 季節 / 厚さ / テイスト」を一覧表示する。
警告はアプリが既定値で補った箇所なので、意図したものか確認して直す。id の重複はここで NG になる。

### 5. 渡し方

- JSON はファイルに保存する。既定は `wardrobe-import.json` (リポジトリ直下。`.gitignore` 済みなので個人の服データがコミットされない)。
  ユーザーが別のパスや Gist のファイル名を言えばそれに従う。
- チャットには JSON 全文と、validate の一覧を見せる。
- Gist 運用の案内は短く: 「Gist に `wardrobe.json` として貼る → アプリの『インポート』に Gist の URL を貼る → 以後は Gist を直して『読み込む』だけ」。
- ユーザーが **既存の Gist / JSON を持っている** なら、追加分だけ渡すのではなく、既存を取得して id でマージした全体を返す
  (Gist の Raw URL は `curl -sL` で取れる)。アプリ側の「既存に追加」でも同じ結果になるが、Gist 本体を正にしておく方が後で楽。

## 聞いてよいこと・聞かずに進めること

- **聞く**: 持っている色 (色違いが複数あるとき)。これはどこにも書いていない。
- **聞かない**: warmth・seasons・formality の細部。合理的に推定して、推定した旨と根拠を添える。ユーザーはアプリ上でも直せる。
- 商品ページが取れなかったときは「取れなかった」で止まらず、必要な 4 項目 (商品名・色・素材・種類) の貼り付けを具体的に頼む。

## 例

入力: 「ユニクロの https://www.uniqlo.com/jp/ja/products/E486119-000/00 を買った。色はダークグレー」

1. スクリプトで取得 → name=スウェットフルジップパーカ, class=tops, composition=綿100%, colors に 08 DARK GRAY
2. category=tops / color=#4a4a4a / warmth=3 (綿スウェット) / seasons=春秋冬 / formality=casual / tags=[スウェット, パーカ, 綿100%]
3. id=`uniqlo-486119-08`, imageUrl=色 08 の image
4. validate → 警告なし → `wardrobe-import.json` に保存して JSON と一覧を提示
